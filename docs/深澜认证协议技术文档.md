# 深澜认证协议（Srun Portal）技术文档

本文记录 LinkUp 当前实际使用的深澜认证协议行为，以及对应的 Dart 实现位置。不同学校的部署版本可能调整页面或字段；修改协议实现时，应同时核对真实 Portal 响应和本文。

## 1. 实现边界

| 领域 | 实现位置 |
| --- | --- |
| CGI 请求与 JSONP | `lib/utils/SrunClient.dart` |
| 登录参数、错误分类 | `lib/utils/SrunLogin.dart` |
| HMAC-MD5、XXTEA、Base64、SHA-1 | `lib/utils/SrunEncrypt.dart` |
| ACID、Enc、重定向与在线探测 | `lib/utils/AcidDetector.dart` |
| 单次认证协调、参数快照与 ACID 候选 | `lib/utils/AuthenticationCoordinator.dart`、`lib/utils/AuthParameters.dart` |
| 生产协议适配器 | `lib/utils/SrunAuthenticationProtocol.dart` |
| 用户信息模型 | `lib/utils/RadUserInfo.dart` |
| Challenge 模型 | `lib/utils/ChallengeResponse.dart` |

认证请求统一使用 `http`；`dio` 只用于下载 APK，不属于协议层。

## 2. 编码与响应格式

### Latin-1

深澜算法中的密码、Challenge 和待加密 JSON 都按 Latin-1（ISO-8859-1）字节处理。`SrunEncrypt` 对这些输入使用 `latin1.encode()`，不能改成 UTF-8，否则摘要、XXTEA 密文和校验和都会变化。

### JSONP

CGI 响应通常不是纯 JSON，而是：

```text
jQueryCallback({"error":"ok", ...})
```

部分 Portal 会生成随机 callback 名称。处理顺序为：

1. 优先用请求中的 callback 名称和首尾括号提取 JSON。
2. 登录请求的回退逻辑可用首尾括号定位 JSON。
3. 对提取出的字符串执行 `jsonDecode`。
4. 保留原始 HTTP 状态码和 Portal 错误字段，不用解析失败掩盖网络错误。

`rad_user_info` 的 `online_device_detail` 仍是 JSON 字符串，映射到模型后需要再次 `jsonDecode` 才能得到 `OnlineDevice` 列表。

## 3. CGI 端点

认证服务器基地址默认为 `http://<host>/cgi-bin`。

| 端点 | 用途 | 关键字段 |
| --- | --- | --- |
| `/rad_user_info` | 查询客户端 IP、流量、时长、在线设备与在线状态 | `error`、`online_ip`、`client_ip`、`sum_bytes`、`sum_seconds`、`online_device_detail` |
| `/get_challenge` | 获取短期 Challenge | `challenge`、`client_ip`、`online_ip`、`ecode`、`expire` |
| `/srun_portal` | 提交登录请求 | `error`、`error_msg`、`res`、`suc_msg` |
| `/rad_user_dm` | DM 注销 | `error` |

LinkUp 当前没有实现 `/v1/srun_portal_online` 或 `:8800/site`；已实现端点以本表和对应代码为准。

## 4. 登录链路

1. `AuthenticationCoordinator` 读取当前网络世代、确认 Wi-Fi 连接并加载认证配置。
2. 协调器通过 `AcidDetector.reality()` 执行 Reality 探测，并按当前模式保留可用的 ACID 候选及其网络世代。
3. `SrunClient.getUserInfo()` 查询当前 IP 与在线状态；该结果是登录前和登录后的在线事实来源。
4. 若需要登录，按当前模式选择 ACID：自动模式为 Reality → 已保存值 → 根目录探测，手动模式只使用已保存值。配置模型以 `hasExplicitAcid` 区分默认运行时值和明确保存的空值。
5. 协调器创建不可变 `AuthParameters`，限制 Enc 为当前支持的 `srun_bx1`，并调用 `/get_challenge?username=...&ip=...` 获取 Challenge。
6. `SrunLogin.login()` 只从该参数对象生成 Info、Chkstr、checksum 和请求字段，提交 `/srun_portal`。
7. 登录响应解析后，再次调用 `rad_user_info` 确认真实在线状态；确认前不保存候选 ACID。

`rad_user_info` 返回 `error == "ok"` 表示在线，`not_online_error` 表示当前未认证。`srun_portal` 的成功响应不足以证明设备已经获得网络访问权限。登录失败、取消、网络世代变化或在线确认失败都会使本轮候选失效；只有确认在线后才通过带世代条件的局部 `ConfigUpdate(acid: ...)` 保存实际使用的 ACID。

### Challenge 成功条件

`ChallengeResponse.isSuccess` 要求：

```text
error == "ok" && ecode == 0
```

Challenge 为空时不能继续登录。

## 5. 认证参数生成

### 5.1 HMD5

```text
hmd5 = lowercase_hex(HMAC-MD5(key=challenge, message=password))
```

请求参数格式：

```text
password={MD5}<hmd5>
```

当前只实现 MD5 密码方案，没有实现 OTP 分支。

### 5.2 Info

先构造以下 JSON，字段顺序由 Dart `Map` 保持：

```json
{
  "username": "...",
  "password": "...",
  "ip": "...",
  "acid": "...",
  "enc_ver": "srun_bx1"
}
```

每轮认证先创建不可变 `AuthParameters`。它携带认证服务器、最终用户名、IP、ACID、`n`、`type`、callback 和受支持的 Enc；密码与 Challenge 不放入可观察参数对象。随后按以下顺序处理：

1. 将 JSON 按 Latin-1 编码。
2. 以 Challenge 为密钥执行 XXTEA。
3. 对密文执行深澜自定义 Base64。
4. 添加协议头 `{SRBX1}`。

### 5.3 Chkstr 与 Chksum

当前实现拼接：

```text
challenge
+ username
+ challenge
+ hmd5
+ challenge
+ ac_id
+ challenge
+ ip
+ challenge
+ n
+ challenge
+ type
+ challenge
+ info
```

然后计算：

```text
chksum = lowercase_hex(SHA1(chkstr))
```

登录请求中的 `n=200`、`type=1` 与 `Chkstr` 的对应字段都来自同一 `AuthParameters`。`enc=srun_bx1` 只进入 Info 的 `enc_ver` 和协议前缀，不替代 `Chkstr` 中的 `type`。页面探测到的其他 Enc 只保留为脱敏诊断信息，不能进入登录参数。

## 6. XXTEA 细节

`SrunEncrypt` 的实现参数如下：

| 项目 | 值 |
| --- | --- |
| 模式 | 将整段填充后的明文作为一个 XXTEA 数据块处理，不接收独立 IV 参数 |
| 字节序 | 小端序 |
| Delta | `0x9E3779B9` |
| 轮数 | `floor(6 + 52 / (n + 1))`，其中 `n = 数据块数 - 1` |
| 密钥 | Challenge 的 Latin-1 字节按小端序组成 32 位整数，取前 4 个并补零 |
| 填充 | 数据末尾不足 4 字节时补零，最后一个整数保存原始明文字节数 |
| 输出 | 将整数数组按小端序写回字节 |

Go/JavaScript 实现可能把 Delta 写成 `0x86014019 | 0x183639A0`；Dart 中直接使用无符号 32 位值 `0x9E3779B9`。

## 7. 自定义 Base64

标准字母表：

```text
ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/
```

深澜字母表：

```text
LVoJPiCN2R8G90yg+hmFHuacZ1OWMnrsSTXkYpUq/3dlbfKwv6xztjI7DeBE45QA
```

LinkUp 先用标准 Base64 编码，再按相同字符位置逐字替换。这个结果与直接使用深澜字母表执行 3 字节到 4 字符的 Base64 编码等价。

## 8. ACID 与 Enc 探测

### ACID

需要登录时，`AuthenticationCoordinator` 为本轮认证创建一个带来源和网络世代的 ACID 候选。自动模式严格按以下顺序选择：

```text
Reality 捕获 → 已保存值 → 认证服务器根目录探测
```

Reality 已返回非空 ACID 时不得执行根目录探测。手动模式跳过根目录探测，只使用已保存值；`AcidDetector` 仍可独立执行 Reality 在线判断，但其 ACID 不会覆盖手动选择。

`AcidDetector` 不遍历常见值猜测 ACID，而是优先解析 Portal 页面：

1. 跟随重定向链，从每一跳 URL 的 `ac_id`、`acid` 或 `Acid` 参数读取值。
2. 若 URL 没有值，请求登录页，从隐藏表单的 `ac_id` 输入框读取。
3. 还支持从 `ac_id = "..."` 或 `ac_id: "..."` 形式的 JavaScript 字面量读取。

HTTP 客户端关闭自动重定向，`_followRedirect` 最多跟随 10 跳，并处理：

- 3xx `Location`；
- `top.self.location.href='...'` JavaScript 跳转；
- `<meta http-equiv="refresh" ... url=...>` 跳转。

恢复自动重定向会跳过中间 URL，破坏 ACID 探测。

### Reality

`reality()` 并发请求以下入口，首个成功结果胜出：

1. `http://www.msftconnecttest.com/connecttest.txt`
2. `http://captive.apple.com/hotspot-detect.html`
3. `http://connectivitycheck.gstatic.com/generate_204`
4. `http://detectportal.firefox.com/canonical.html`
5. `http://www.baidu.com`

只有最终 host 与入口 host 相同，且响应体不含 Portal 特征时，才判定为在线。Portal 特征包括 `srun_portal`、`login.html`、ACID 表单或常见 ACID 脚本片段。协调器在发现网络世代或认证服务器变化时重置探测缓存；已在飞行中的旧请求不得把页面写回新世代缓存。

### Enc

`detectEnc()` 从登录页找到 `portal*.js`，再从脚本中提取 `var enc = ...`，并可拼接 `"srun" + "_" + "bx1"` 这类字符串。当前协议实现只把 `srun_bx1` 写入认证参数；其他探测结果只保留为脱敏诊断值。LinkUp 尚未实现从页面单独探测客户端 IP 的逻辑。

## 9. DM 注销

注销不使用登录的 `info` 加密链。`rad_user_dm` 的签名为：

```text
sign = SHA1(time + username + ip + 1 + time)
```

同时提交 `time`、`username`、`ip`、`unbind=1` 和 `sign`。

## 10. 常见错误

| 错误 | 含义与处理 |
| --- | --- |
| `E2901` | 密码错误或账号不存在；检查凭据和账号后缀 |
| `E2902` | 账号不存在或已停用；联系网络中心 |
| `E2905` | 账号欠费停机；充值后重试 |
| `E2553` | 密码错误或加密方式不匹配；检查 Latin-1/HMD5/Info 链路 |
| `E2606` | 用户被禁用；联系网络中心 |
| `E3001` | 流量或时长用尽；充值或购买流量包 |
| `E2620` | 同时在线设备数超限；下线其他设备后重试 |
| `E2821` | IP 不在线；检查 Wi-Fi 和地址获取 |
| `E2833` | IP 已被占用；等待地址释放或重新联网 |
| `E2602` | 认证设备响应超时；稍后重试 |
| `ip_already_online_error` | IP 已被其他账号占用；先注销或重连换 IP |
| `not_online_error` | `rad_user_info` 的正常离线状态 |
| `ACID error` | 接入点不匹配；重新自动探测或手动确认 ACID |

`SrunLogin` 还会根据 `error_msg` 和 `res` 中的关键词做兼容分类，因此新增服务端文案时应同步更新错误分类测试或映射。

## 11. 修改协议代码时的验证点

- Latin-1 输入与 HMAC-MD5/SHA-1 已知答案保持一致。
- JSONP callback 和括号回退均能解析。
- `info` 包含 `{SRBX1}`，`password` 包含 `{MD5}`。
- `Chkstr` 字段顺序和动态值未改变。
- 登录后通过 `rad_user_info` 二次确认在线。
- ACID 探测仍检查每一跳 URL、隐藏表单和 JavaScript 赋值。
- 日志与测试输出不包含密码、Challenge、完整 `info`、HMD5 或签名。
