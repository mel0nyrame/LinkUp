# 由认证协调器管理监控调度与自适应退避

- **状态**：Active / implemented
- **日期**：2026-09-25
- **范围**：LinkUp Android 客户端的在线监控生命周期

## Problem

旧实现由 Widget 持有 3 秒周期 Timer，并直接触发认证协调器。一次 Reality 探测、在线确认或登录耗时超过检查周期时，下一次检查会与当前流程重叠，共享同一协议实例和 Portal 缓存。Timer、网络变化与手动刷新也没有统一入口，无法区分立即执行、合并或拒绝。固定 3 秒重试在长期离线时持续请求，而停止、注销和配置变化不会取消旧调度或释放协议资源。

## Decision

`AuthenticationCoordinator` 通过可替换的 `AuthenticationScheduler` 管理监控生命周期。UI 发送启动、网络变化、手动刷新、注销和配置变化命令，并只渲染协调器发布的状态；UI 不创建认证周期 Timer。

“在线检查 → ACID 候选解析 → Challenge → 登录 → `rad_user_info` 二次确认 → 持久化”由同一把单飞锁保护。锁在最外层完成回调中释放。执行期间到达的 Timer、网络和手动触发不会并行启动第二轮流程，而是合并为至多一次后续检查；合并检查保留手动模式意图，不取消正在进行的登录。

每轮检查结束后才安排下一次执行：

- `rad_user_info` 确认在线后使用 30 秒周期，并把连续失败计数清零；
- 离线、失败、取消或世代失效从 3 秒开始指数退避，最大 60 秒；
- 停止、注销和配置变化不清零失败计数，因为这些事件没有产生在线确认；
- 网络变化和手动刷新取消待执行的退避任务，并立即通过同一单飞入口请求检查。

停止、注销、删除配置和认证服务器变化会取消调度、使当前网络世代失效、等待在途检查结束，并通过协议边界重置 Portal 缓存和释放 HTTP client。协议实现由 `protocolFactory` 重建，以便后续监控使用新的传输资源。未提供工厂的一次性协议在释放后不会被复用。删除配置后协调器保持停止，直到后续命令重新启动监控。

协调器至少发布 `stopped`、`checking`、`authenticating`、`online`、`offline` 和 `backingOff` 状态；`backingOff` 状态携带下一次重试间隔。

## Alternatives considered

- **继续由 UI Timer 固定每 3 秒触发**：改动小，但无法避免慢 Reality 与下一次检查重叠，也无法在 Widget 销毁后可靠管理退避和资源，因此不采用。
- **新触发到达时取消正在执行的认证并立即重启**：能够缩短响应时间，但会在登录或持久化中途留下不一致状态，也可能重复提交 Portal 请求，因此不采用。
- **执行期间直接拒绝所有新触发**：实现简单，但会让有效网络变化丢失立即重试机会，因此改为合并为至多一次后续检查。
- **失败时固定 3 秒重试**：逻辑最少，但长期离线或服务不可达时持续高频请求，因此采用有上限的指数退避。
- **停止或修改配置时清零失败计数**：可以让新配置立即回到最短间隔，但会伪造“已经恢复”的前提，违背只有 `rad_user_info` 能确认在线的约束，因此不采用。
- **停止时只取消调度而保留 HTTP client**：重启更快，但无法满足认证运行时按生命周期释放资源的要求，因此停止和注销同时释放协议资源。

## Consequences / Risks

- 调度器是确定性测试 seam；退避周期、单飞合并和资源释放不需要真实计时器或校园网。
- 协调器是生产路径唯一需要提供 `protocolFactory` 的地方；否则协调器只能安全执行到第一次释放。
- 配置保存和删除通过 Widget 回调通知协调器。漏接的调用方不会自动取消旧调度或释放资源。
- `connectivity_plus` 仍不能区分所有同类型 Wi-Fi 网络；网络世代失效继续依赖平台实际发出连接变化事件。
- 后续 Android 前台服务可以复用同一协调器、调度器和状态流，但服务生命周期与开机行为不属于本决策范围。

## Reintroduction conditions

只有在重新评估 Flutter isolate 生命周期、Android 后台调度限制、网络事件来源和认证协议请求代价后，才可以替换协调器监控边界或恢复 UI 周期 Timer。替换实现必须保留完整生命周期单飞、触发合并、在线确认后清零退避、停止时世代失效与资源释放约束。
