# 限制诊断日志的内容与保留范围

- **状态**：Active / implemented
- **日期**：2026-09-26
- **范围**：Android 客户端的本地诊断日志

## Problem

认证与更新路径都需要故障记录，但异常文本和带查询参数的 URL 可能包含账号、密码、Challenge 或下载令牌。日志文件保存在应用文档目录，原实现持续追加且没有大小上限；普通文档目录还可能进入 Android 备份。

## Decision

`LogUtil` 是 Dart 侧写入 `error.log` 的入口。它在写入边界移除 URL 查询参数和已知认证字段的值，异常只记录类型与堆栈；调用方仍不得主动把无标签的秘密拼进消息。日志写入串行执行，文件超过 1 MiB 时只保留末尾约 512 KiB。更新检查与 APK 下载的异常进入同一入口，不直接打印异常。Android 云备份与设备迁移都排除 `error.log`。

`LogUtil` 只负责诊断，不影响认证结果或更新结果。初始化、写入、读取或清理失败时不得把原始异常或待写内容转发到标准输出。

## Alternatives considered

- **继续依赖每个调用方手工遮盖字段**：新增调用点容易漏掉，且无法限制文件增长或备份范围。
- **记录完整异常与 HTTP URL 以增加调试细节**：异常可能包含完整请求地址或服务端回显；其诊断收益不足以承担凭据泄漏风险。
- **完全停用持久化日志**：可消除本地文件风险，但用户无法在离线和后台运行场景中提供诊断记录。

## Consequences / Risks

轮转会丢弃旧会话，异常值与 URL 查询参数也无法用于定位故障。字段脱敏只能识别带名称的值；因此调用方仍须避免把无标签的凭据写入自由文本。日志内容可能包含其他用户信息，故同时通过备份排除降低传播范围。`test/log_util_test.dart` 验证写入边界的脱敏与文件上限；Android 备份规则需与该决策同步维护。

## Reintroduction conditions

增加日志详情前必须证明新增字段不含认证材料，并保持写入边界的脱敏、容量限制与备份排除。若改用远端日志，还需单独决定用户同意、传输与保留策略。
