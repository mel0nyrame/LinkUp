# 跨行为路径的 PR 正文先经独立预审

- **状态**：Active / implemented
- **日期**：2026-09-27
- **范围**：涉及多条行为调用链或所有权边界的 PR 正文

## Problem

五节齐全的 PR 正文仍可能只罗列文件和改动项，评审者需要从原始差异重新推导行为、所有权与调用顺序。代码的双轴 review 检查实现和规格，不检查随后撰写的正文；作者自行复读草稿也容易沿用写作时的隐含上下文。

## Decision

这类 PR 在发布前由未参与撰写的只读 reviewer 预审完整正文。reviewer 先独立阅读草稿，再对照需求来源与完整差异，检查关键变化能否从正文直接理解、事实是否准确、证据是否紧邻对应主张。具体触发条件、输入与通过标准由 [交付约定](../agents/delivery.md) 负责。

预审只处理正文；代码 Review Gate 和作者的发布责任保持各自独立。单一局部行为改动不增加独立预审。

## Alternatives considered

- **只校验五节标题与必填字段**：能发现缺节，无法判断轮廓是否仍是文件清单，也无法发现行为证据错位。
- **由作者自行复读草稿**：成本低，但与撰写共享同一上下文，难以发现评审者无法补全的关系。
- **所有 PR 都执行独立预审**：对单一局部改动增加额外审阅成本，收益不足。

## Consequences / Risks

跨行为路径的 PR 多一次只读审阅和必要的改写。正文质量仍属于语义判断，不能靠格式脚本证明；reviewer 必须有草稿、需求来源和完整差异，预审通过也不代表代码正确。
